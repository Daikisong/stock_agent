## 4. Collaboration journal 확인

request와 response는 같은 `COLLABREQ-...json` 파일명으로 대응한다. 응답 payload는 deterministic importer가 schema와 request identity를 확인한 뒤 저장한다.

```bash
python - <<'PY'
from pathlib import Path
import json

root = Path("output/researcher_mode/c06/2026-07-12-clean-v8/000660/collaboration_codex_subagent_provider")
responses = {p.name for p in (root / "responses").glob("COLLABREQ-*.json")}
for request in sorted((root / "requests").glob("COLLABREQ-*.json")):
    if request.name in responses:
        continue
    row = json.loads(request.read_text())
    print(request.name, row.get("pass_name"), row.get("schema_name"))
PY
```

현재 출력되는 사실추출 request 하나는 quarantine 뒤 대체된 historical residue다. canonical fact result의 pending reason은 비어 있다. 현재 조치 대상은 `SOURCE_QUERY_GENERATION` request다.

## 5. 외부 분석 결과에 포함할 답

외부 검토자는 최소한 다음을 명시해 주는 것이 좋다.

1. 현재 query lane을 새 fetch 없이 닫아도 되는가.
2. 그 근거가 어떤 checkpoint/history field에 있는가.
3. 닫은 뒤 `score_valid`를 유지하거나 보류할 정확한 조건은 무엇인가.
4. 어떤 component가 corroboration 공백의 영향을 받아야 하는가.
5. 무한 재검색을 막는 최소 코드 변경과 회귀 테스트는 무엇인가.
6. 현재 snapshot에서 미래 데이터 누수나 LLM score authority가 발견되는가.

## 6. 변경 제안 검증

코드를 수정한다면 기본 테스트를 실행한다.

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

전체 테스트가 오래 걸리더라도 일부 테스트 성공만으로 `PRODUCTION_READY`를 선언하면 안 된다. 최소한 Source Graph acquisition, Phase94 runner contract, semantic saturation, fact extraction, tracked receipt 테스트를 별도로 확인해야 한다.

## 7. 결과 언어

직접적인 투자 권고는 사용하지 않는다. 결과는 다음과 같은 모니터링 언어로 표현한다.

- `information_confidence 제한`
- `고객 공식 corroboration 미확인`
- `score pending` 또는 `score valid`의 구체 사유
- `Stage 0 보류`가 필요한지 여부
- `다음 실적·수주잔고·계약조건 확인`
