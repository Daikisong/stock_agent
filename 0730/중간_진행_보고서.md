## 1. 지금 어떤 방식으로 진행 중인가

현재 작업은 점수가 낮다는 이유로 문서나 fact를 계속 추가하는 방식이 아니다. 각 종목의 target leaf에서 `RESEARCH_CHECKPOINT_PENDING`을 만든 정확한 completion gate를 찾고, 그 gate를 만든 실제 데이터 계보만 수리한 뒤 같은 checkpoint를 clean resume하고 있다.

쉬운 예:

- 저장된 값이 문자열 `"104.1"`이면 exact grounding은 따옴표까지 포함한 JSON 문자열을 요구한다.
- 하지만 분석 모델은 이를 자연스럽게 숫자 `104.1`로 반환했다.
- 둘의 경제적 의미는 같아 보여도 재현 가능한 exact grounding에서는 타입이 다르므로 component가 pending이 됐다.
- 해결은 비교를 느슨하게 만드는 것이 아니라, 원래 숫자인 값을 EvidenceFact에 숫자로 저장하도록 원천 타입을 복원하는 것이다.

현재 production 흐름은 아래 순서로 진행된다.

1. 기존 문서·claim·fact를 `as_of_date` 기준으로 재개한다.
2. fact 값의 손상된 표현과 원래 JSON 타입만 복원한다.
3. business-model memo를 다시 만든다.
4. 7개 component를 각각 여러 loss-accounted 청크로 검토한다.
5. 각 청크는 source value, period, predicate, economic mechanism을 exact 대조한다.
6. 최초 응답이 원문 필드를 요약하면 격리하고 1회 교정한다.
7. 모든 청크와 synthesis가 `research_complete=true`여야 해당 component가 닫힌다.
8. 이후 Judge, Red Team, Supervisor, deterministic score, `score_valid=true`, FINAL StageCourt로 진행한다.
9. production complete 뒤에만 격리된 Gold post-run comparison을 수행한다.

### 2.13 Codex collaboration subagent bridge

Codex CLI 사용량 제한을 Qwen으로 우회하지 않는다. 대신 Codex
collaboration subagent가 같은 동적 schema와 full prompt를 검토할 수 있는
별도 journal bridge를 추가하고 있다.

안전 계약:

- 정상 Codex CLI의 정확한 cache hit를 항상 먼저 쓴다.
- cache miss이고 실제 실패 원인이 `USAGE_LIMIT`일 때만 subagent request를
  만든다.
- request에는 pass, full prompt, 동적 JSON Schema, prompt/schema/provider
  hash, 결정적 request id를 저장한다.
- subagent 응답은 정상 Codex CLI cache에 손으로 쓰지 않는다.
- 별도 response namespace에서 Draft 2020-12 schema, blind-output,
  request hash, agent id와 canonical task를 검증한다.
- provenance는 `ORCHESTRATOR_ATTESTED_NOT_CRYPTOGRAPHIC`으로 명시한다.
- LLM 응답은 score/Stage 권한이 없고, 기존 downstream semantic validator를
  다시 통과해야 한다.
- semantic validation 실패 응답은 quarantine하고 새 prompt request로
  재검토한다.
- Qwen/Ollama fallback은 사용하지 않는다.

청크형 pass는 이미 CLI cache에 있는 청크를 다시 요청하지 않도록
candidate partition·fact chunk·component chunk·synthesis 각각의 leaf에서만
fallback한다.

독립 감사에서 찾은 bridge 문제도 production resume 전에 모두 닫았다.

- 서로 다른 두 응답의 동시 import 덮어쓰기: first-writer-wins CAS로 수리
- 잘못된 response id의 quarantine 경로 이탈: raw bytes hash 내부 ID로 수리
- 변조 파일을 validated로 세던 audit: request/envelope 재검증 집계로 수리
